# Media

Product images and videos for the README and the website. Every file here is generated by
`pnpm media` from the real extension and the real `lanehead` CLI, in headless Chromium. Do not
edit these files by hand.

**Run `pnpm media` after any UI change, then check the files and commit them.**

## Files

| File | What it shows |
|---|---|
| `hero.mp4`, `hero.webm`, `hero.gif`, `hero.png` | Two tabs on shop.example.com: Cart on lane `feature_checkout`, Search on `staging`. Switching tabs, the page shows the headers its server received and the popup shows that tab's lane. |
| `switch.*` | In the popup: click `feature_search`, the "Reload tab" band appears, reload, and the page shows the new `x-env`. Then the same with keys: `1`, then `R`. |
| `edit.*` | In the popup: **+ Add header**, type `x-debug`, Tab, `1`, Enter (saved to the lane), reload, and the page shows `x-debug: 1`. |
| `agent.*` | A terminal runs `lanehead tabs --url shop.example.com`, then `lanehead set <id> -p feature_checkout --reload`. The browser tab reloads with the new headers and its badge changes. The output in the terminal is the real output of those commands. |
| `popup-dark.png`, `popup-light.png` | The popup (2x): a tab on `feature_checkout`, plus an `x-debug` header set for this tab only. |
| `manage-dark.png`, `manage-light.png` | The manage page's Tabs section (2x): five tabs, each with its own lane. |

Each video comes in four files:

- `.mp4`: H.264, yuv420p, faststart, no audio, 1920×1200, 30 fps.
- `.webm`: VP9, the same size.
- `.gif`: about 900 px wide, at most 4 MB, for the README.
- `.png`: the poster. This is the first frame, except for `agent.png`, which shows the finished run.

Each loop is 11–13 s long and fades back into its first frame.

## How they are made

`scripts/media/` (`pnpm media` builds the e2e extension and the CLI, then runs
`scripts/media/media.spec.ts` with `scripts/media/playwright.config.ts`):

- `echo.ts` is an HTTPS server on loopback that renders the request headers it received. The
  browser runs with `--host-resolver-rules` mapping `*.example.com` to it, so the headers on the
  page are the ones Lanehead actually sent. Requests intercepted by Playwright routes would not
  show them.
- `fixtures.ts` builds on `tests/e2e/fixtures.ts`. For the agent scene it registers the native
  host with the real `lanehead install` in a scratch home and profile, as
  `tests/e2e/agent.spec.ts` does.
- `film.ts` and `stage.html` handle composition. Headless Chromium has no browser UI, so a
  window frame (tab strip, address bar, extension button) and a terminal are drawn around the
  captures. Everything inside the frame is captured from the real run: page and popup
  screenshots, the extension's badge text and color (`chrome.action`), and the CLI output. The
  cursor, click rings and keycaps show what the script does to the real popup.
- Frames are rendered at a fixed 30 fps of virtual time, so pacing is the same on every machine.
  ffmpeg encodes them.

Requirements are ffmpeg (with libx264 and libvpx-vp9) and openssl. The pipeline looks for
ffmpeg on `PATH`, then in Homebrew's location, or uses the path in `FFMPEG`. A full run takes
about a minute.
