Every tab, its own backend.

Lanehead gives each Chrome tab its own request headers. Put one tab on x-env: lane_a and the next on lane_b, side by side. Your coding agent can switch them too.

Try it here.

This is Lanehead's real popup and its real header logic, running in this page. Switch tabs, pick a lane, reload. Or type a lanehead command, like an agent would.

Your agent picks the lane.

One command puts a tab in a lane, then the agent navigates. Every command prints one line of JSON. 

$ lanehead set 1842 -H 'x-env: lane_a'
{"id":1842,"lane":"custom","headers":{"x-env":"lane_a"}}

How agent control works →

Switch in a keystroke.

Open the popup with AltShiftH, press 1–9 for a lane, R to reload. The toolbar badge shows each tab's lane in its color.

Edit a lane once, every tab follows.

A lane is a named set of headers. Add or change one right in the popup; every tab on that lane sends it from the next request.

Isolated by default

A new tab sends nothing extra. Only the tabs you put in a lane send its headers, so the rest of your browsing is untouched.

Opened tabs inherit

Links, ⌘-clicks and window.open from a tab in a lane open in the same lane. You can turn that off.

Stays on your machine

No account, no telemetry, no network requests. Chrome's own declarativeNetRequest rules add the headers; nothing reads your traffic.

Install.

Lanehead isn't on the Chrome Web Store. You load it from GitHub, in a minute.

  1. 1

    Download

    Get lanehead-chrome.zip from the latest release and unzip it somewhere it can stay.

  2. 2

    Load unpacked

    Open chrome://extensions, turn on Developer mode, click Load unpacked and pick the folder.

  3. 3

    Pin it

    Pin Lanehead to the toolbar, open it on any tab, and create your first lane.
